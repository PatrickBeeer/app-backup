# 真人带货视频复刻工作台设计规格

## 1. 产品目标

构建一个本地 Web 工作台。用户上传一条不限时长的真人带货参考视频、3–5 张已授权真人照片和新商品资料后，应用自动复刻参考视频的镜头结构、时长、场景、服装风格、道具、动作、运镜、剪辑节奏、声音氛围和画面文字，只替换人物身份、商品与对应口播，最终交付一条 720p 可下载 MP4。

“完全一样”在产品内定义为结构级高保真：镜头顺序、时间点、构图意图、动作、运镜、场景、道具、服装风格和声音节奏均以参考片为约束；生成模型无法保证像素级相同，因此系统必须提供自动技术质检、问题片段标记和人工接受/重做/替换的兜底流程。

## 2. 已确认范围

- 参考视频：仅支持本地 MP4、MOV、WebM 上传。
- 视频长度：不设产品时长上下限；仅受 200 MB 上传上限和生成任务数影响。
- 输出画幅：项目创建时选择 9:16 或 16:9；与参考片不同时重新适配构图，保留镜头顺序、时长、动作与运镜。
- 输出分辨率：首版固定 720p。
- 输出数量：每项目只交付一个最终版本。
- 人物：上传 3–5 张同一位授权真人的照片，不复制参考片人物身份。
- 商品：上传商品图片，手动填写名称、价格、卖点、规格、必说内容和禁用表达。
- 口播：系统自动按原片语音段落数量、顺序、停顿和时间位置生成新商品口播，不要求用户逐句编辑。
- 声音：不接独立 TTS、不克隆声音、不接额外口型模型；Seedance 2.0 原生生成中文人声、口型、音乐、环境声与音效，并参考原片的节奏和情绪。
- 拆镜：全自动识别，不提供人工调整切点。
- 付费闸门：展示拆镜、生成单元、新口播、替换方案和任务数量，用户一次确认后再批量生成。
- 审核：系统自动重试技术不合格任务；仍有问题时标红，用户可接受、重做或上传替代片段。
- 字幕与文字：识别原片文字的内容、位置、样式和出现时间，使用新商品内容重新渲染，避免依赖视频模型生成可读文字。

## 3. 非目标

- 首版不支持平台链接解析、账号系统、计费、云部署、多人协作或移动端原生应用。
- 首版不做声音克隆、独立 TTS、独立口型驱动或同时生成多套完整版本。
- 首版不承诺像素级复制，也不提供水印移除、未经授权的人脸/声音复制或原台词逐字抄袭功能。
- 首版不开放 4K。

## 4. 用户流程

1. 新建项目，选择 9:16 或 16:9，上传参考视频。
2. 上传 3–5 张人物照片和 1–9 张商品图片，填写商品事实与表达约束。
3. 点击“开始分析”。应用读取媒体参数、检测切镜与语音停顿、抽取代表帧、分析字幕/贴纸样式，并生成新口播。
4. 应用把真实镜头组合成 4–15 秒的 Seedance 生成单元。确认页展示参考片段、真实镜头、生成单元、新口播、商品替换说明和预计任务数。
5. 用户一次确认后，应用发布输入媒体并批量提交异步任务。
6. 后台轮询并下载临时结果；对时长、画幅、分辨率、音轨或解码异常的片段自动重试一次。
7. 审核页仅突出问题片段。用户可接受当前结果、再次生成或上传替代视频。
8. 全部单元通过后，应用按原时间线裁切、归一化、拼接，重新渲染字幕/贴纸并导出最终 MP4。

## 5. 生成单元算法

参考片的真实镜头边界是唯一剪辑基准。由于视频接口的单次时长只能是 4–15 秒，应用不能机械地让每个真实镜头对应一次请求。

组合规则：

1. 先获得 `[start, end]` 真实镜头序列。
2. 超过 15 秒的单镜头按不超过 15 秒切成技术片段。
3. 从左到右累积相邻片段，优先在真实切点结束，使每个生成单元落入 4–15 秒。
4. 尾部不足 4 秒时并入前一单元；若并入会超过 15 秒，则从前一单元向尾部移动最近的完整镜头。
5. API 的 `duration` 取覆盖该单元所需的 4–15 秒整数；下载后按真实单元时长精确裁切。
6. 最终合成再次按原始镜头时间点切回，保证剪辑时间线不漂移。

## 6. 模型与接口

正式环境：`https://ai-api.cprt.xyz`，认证使用服务端 `Authorization: Bearer`，密钥仅从 `.env` 读取。

### 主视频模型

`free-video-2.0-multimodal-video`

```json
{
  "model": "free-video-2.0-multimodal-video",
  "prompt": "结构化的复刻指令与该单元的新口播",
  "resolution": "720p",
  "duration": 8,
  "imageUrls": ["人物照片 URL", "商品图片 URL"],
  "videoUrls": ["原片生成单元 URL"],
  "audioUrls": ["原片生成单元音频 URL"],
  "generateAudio": true,
  "ratio": "9:16",
  "realPersonMode": true,
  "conversionSlots": ["image1", "image2", "image3"],
  "returnLastFrame": true,
  "seed": -1
}
```

人物照片必须排在 `imageUrls` 前部，`conversionSlots` 只包含对应的人物图片槽位，不能资产化原参考视频人物。商品图片随后排列，通过提示词约束商品外观。

### 备用视频模型

`free-video-2.0-image-to-video`

主模型提交失败，或生成单元缺少可用参考视频时，使用生成单元首帧/尾帧调用备用模型。备用模型不承担严格动作参考，界面必须标记“首尾帧兜底”。

### 异步协议

- 创建：`POST /v1/chat/asyncTask`
- 查询：`GET /v1/chat/asyncTask/{taskId}`
- 状态：`QUEUED`、`RUNNING`、`SUCCESS`、`FAILED`
- 成功视频：读取 `results` 中 `name = videoUrl` 的 URL并立即下载到项目目录。

### 分析模型

使用同平台 `POST /v1/chat/completions`，默认模型 `奥特曼-5.6-terra`。输入商品事实、抽帧图和本地检测到的镜头/语音段落，要求返回严格 JSON：视频结构、逐段新口播、视觉文字样式和风险项。分析失败时使用确定性的商品事实模板生成口播，保证工作流不被卡死，并在确认页提示分析降级。

## 7. 媒体与存储

- 本地项目文件存于 `data/projects/<project-id>/`。
- 项目与任务状态存入 SQLite，不保存任何 API Key。
- 云端模型只能读取公网 HTTP(S) URL。真实模式优先通过腾讯私有 COS 发布人物图、商品图、参考片段和参考音频；也允许配置一个公开的 `MEDIA_PUBLIC_BASE_URL`。
- COS 返回限时签名 URL；生成结果成功后立即下载到本地，后续播放和合成不依赖远端临时链接。
- 演示模式不调用云端，通过 FFmpeg 生成带有任务标识和音轨的本地候选片段。

## 8. 字幕与画面文字

- 分析阶段从代表帧提取字幕区域、颜色、描边、背景和位置；时间信息以语音段落、镜头和抽帧结果组合推断。
- 生成提示明确要求模型不要绘制可读文字。
- 最终阶段使用 ASS 字幕重新渲染中文口播和商品贴纸。
- 对模型结果中无法可靠清除的错误文字，质检项标记为人工审核，不进行破坏性的大面积涂抹。
- 横竖屏变化时保持原风格，但将文字限制在目标画幅安全区内。

## 9. 状态模型

项目状态：

`DRAFT → ANALYZING → READY_TO_CONFIRM → GENERATING → NEEDS_REVIEW → READY_TO_RENDER → RENDERING → COMPLETED`

任务状态：

`PENDING → SUBMITTING → QUEUED → RUNNING → DOWNLOADING → REVIEW_REQUIRED | ACCEPTED | FAILED`

任何远端任务 ID 都必须持久化。服务重启后继续轮询已有任务，不重复扣费提交。自动重试最多一次；用户主动“再次生成”创建新的尝试并保留旧候选。

## 10. 自动质检

硬性检查：

- 文件可以由 FFprobe 解码。
- 有视频流和音频流。
- 输出为目标画幅附近的 720p。
- 片段实际时长覆盖对应真实单元，误差不超过 0.45 秒。
- 拼接前所有单元都有一个被接受的本地文件。

软性检查：

- 人物、商品、场景、动作、运镜、声音节奏和画面文字是否接近参考。
- 软性项由分析模型评分；模型不可用时显示“待人工核验”，不能伪造通过结论。

## 11. 页面结构

- 项目首页：项目列表、状态、创建时间和继续入口。
- 新建项目：参考视频、输出画幅、人物照片、商品资料一次提交。
- 分析页：阶段进度、媒体信息、镜头和语音段落统计。
- 生成确认页：双轨时间线、生成单元、新口播、商品替换、降级提示和“确认并生成”。
- 任务页：任务状态、失败原因、预计进度。
- 审核页：原片段与候选片段并排，展示质检项，提供接受、重做、上传替代。
- 完成页：成片预览、下载、项目摘要。

视觉风格采用浅暖灰背景、墨黑内容卡、番茄红操作色和荧光青状态色，强调视频工作台而非通用后台；桌面端优先，同时保证 1280px 以下可用。

## 12. 错误处理

- `503`、上游繁忙和短暂网络错误使用指数退避，不立即重复创建付费任务。
- 创建请求响应不含任务 ID 时视为协议错误并保存原始安全摘要。
- 查询到 `FAILED` 保存 `errorCode`、`errorMessage` 和 `failedReason`，敏感头不入日志。
- 缺少 Key 或公网媒体发布器时，真实生成按钮给出配置清单，分析和演示模式仍可使用。
- FFmpeg、FFprobe 或字体不可用时，在启动健康检查和具体步骤中返回可操作错误。

## 13. 验收标准

- 用户可以在无 API Key 的演示模式中走通：创建、自动分析、确认、生成、审核和导出。
- 真实模式请求体符合智算谷 `free-video-2.0-multimodal-video` 文档，并能持久化、轮询、下载结果。
- 任意正时长参考片能被自动拆镜并组合为最长 15 秒的生成单元；不足 4 秒的单元以 4 秒请求生成后按原时间线裁切。
- 人物槽位与商品槽位不会混淆，参考视频人物不进入 `conversionSlots`。
- 用户未确认前不会提交付费视频任务。
- 失败/重启不会重复提交同一远端任务。
- 所有单元接受后可导出目标画幅、720p、有音轨且带字幕的 MP4。
- 自动测试、类型检查和完整演示冒烟测试通过。
